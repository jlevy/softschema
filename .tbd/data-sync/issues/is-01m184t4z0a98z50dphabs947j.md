`split_frontmatter` documents an invariant it does not hold:

> Returns `None` when the document has no frontmatter, matching what
> `read_frontmatter_doc` reports: no leading fence, **an unterminated fence**, or an
> empty block whose end fence is the very next line.

`read_frontmatter_doc` does not report an unterminated fence as "no frontmatter"; it
raises `PortableInputError`. The docstring asserting the equivalence is what made the
divergence look intentional, so correcting it is part of the fix rather than a
follow-up.

State plainly what `None` means to this function's callers — there is no frontmatter
*region to rewrite* — and note that an unterminated fence is a reader error which
profile detection must not read as a fenceless document.

Both languages: packages/python/src/softschema/_portable.py:195, and the matching
comment at the `return None` on the unterminated branch (line 217); the TypeScript twin
at packages/typescript/src/portable.ts:204.
